Tokenization 101: How LLMs Read the World

        

          Everything you need to know about Byte-Pair Encoding (BPE), vocabulary compression, and tokenization quirks.
        

      


      

        
        
        

          
1

          
What is a Token?

          

            LLMs cannot read text directly. Instead, text is sliced into chunks of characters called tokens, which map directly to numbers (integers in a fixed vocabulary). 
            On average, 1 token ≈ 4 characters or 0.75 words in English.
          

        


        
        

          
2

          
How Byte-Pair Encoding Works

          

            BPE begins with raw individual UTF-8 bytes and iteratively merges the most frequently occurring character pairs into new compound tokens (e.g. 't' + 'h' → 'th' → 'the') until reaching the target vocabulary limit.
          

        


        
        

          
3

          
Why LLMs Can't Count Letters

          

            When you ask an LLM "How many 'r's are in strawberry?", it struggles because it does not see the individual letters s-t-r-a-w-b-e-r-r-y. It only sees two abstract token IDs: [straw, berry]!
          

        


        
        

          
4

          
The Multilingual Token Revolution

          

            Older tokenizers (GPT-2, GPT-3) had 50k vocabularies and broke non-Latin languages (Japanese, Hindi, Arabic) into 3 tokens per single character! Modern models (GPT-4o with 200k vocab, Llama 3 with 128k) compress global languages up to 300% more efficiently.
